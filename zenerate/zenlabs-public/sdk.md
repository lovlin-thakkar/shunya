# Using the ZenLabs SDK

The ZenLabs SDK is shared as a **zip bundle** (not yet on PyPI / npm). The bundle contains both languages:

```
zenlabs-sdk.zip
├── python/        ← Python package (pip install)
└── typescript/    ← TypeScript package (pnpm/npm install)
```

The API base URL is:

```
https://zenarate-web-prod.fly.dev
```

---

## Install

Unzip the bundle, then install the language you want.

### Python

```bash
unzip zenlabs-sdk.zip
pip install ./python
```

Verify:

```python
from zenlabs_sdk import ZenClient
```

### TypeScript

```bash
unzip zenlabs-sdk.zip
pnpm add ./typescript     # or:  npm install ./typescript
```

Verify:

```ts
import { ZenClient } from '@zenarate/zenlabs-sdk';
```

## Login

The SDK uses a single header for both authentication and workspace selection:

```
Authorization: Token <api_token> <workspace_id>
```

You can get the token + workspace id either by calling the login endpoint, or by copying them from a session you already have.

### Programmatic login (Python)

```python
from zenlabs_sdk import ZenClient

API_BASE = "https://zenarate-web-prod.fly.dev"

# 1. Bootstrap client (no token yet — login endpoint is unauthenticated)
bootstrap = ZenClient(token="", base_url=API_BASE)

login = bootstrap.auth.token_auth_login_create(
    username="jane@acme.com",
    password="•••••••••",
)

api_token = login.token
workspaces = login.tenants            # [{id, name, slug}, ...]
workspace_id = workspaces[0].id       # pick one — or prompt interactively

# 2. Re-create the client with the combined header
client = ZenClient(
    token=f"{api_token} {workspace_id}",
    base_url=API_BASE,
)

client.auth.me_retrieve()             # sanity check — should return your user
```

### Programmatic login (TypeScript)

```ts
import { ZenClient } from '@zenarate/zenlabs-sdk';

const API_BASE = 'https://zenarate-web-prod.fly.dev';

const bootstrap = new ZenClient({ token: '', baseUrl: API_BASE });

const login = await bootstrap.auth.tokenAuthLoginCreate({
  username: 'jane@acme.com',
  password: '•••••••••',
});

const workspaceId = login.tenants[0].id;

const client = new ZenClient({
  token: `${login.token} ${workspaceId}`,
  baseUrl: API_BASE,
});

await client.auth.meRetrieve();
```

### Skip login — paste an existing token

If you already have a token from the web app (open browser dev tools → look at request headers on any API call), you can skip the login round-trip:

```python
client = ZenClient(
    token="<api_token> <workspace_id>",   # both values, space-separated
    base_url="https://zenarate-web-prod.fly.dev",
)
```

## A few sample calls

```python
# List agents in the active workspace
agents = client.workflow.workflows.list()

# Create a test suite
suite = client.testsuite.test_suites.create(title="Smoke Tests")

# Run every scenario in a suite
client.testsuite.test_suites.run(id=suite.id)

# Read a conversation transcript
convo = client.agentos.conversations.retrieve(id=12345)
```

Errors raise `ApiError`:

```python
from zenlabs_sdk.core.api_error import ApiError

try:
    client.workflow.workflows.retrieve(id=999)
except ApiError as e:
    print(e.status_code, e.body)
```

The full method list is in `python/reference.md` inside the bundle (or `typescript/Client.d.ts` for TypeScript IntelliSense).

## Feeding the SDK to Claude Code

Claude Code is the fastest way to write working SDK scripts without reading every method. Three patterns, ordered by how much context to drop in.

### 1. Reference only (one-off prompts)

Best for "write me a script that does X".

In your Claude Code session:

```
Read python/reference.md from the unzipped SDK bundle.
Then write a script that lists every agent in my workspace and prints
title + node count.
```

The reference is autogenerated and exhaustive — every method, parameter, and return type. Claude indexes it once and produces working code on the first try.

### 2. README + reference (new repos, first-time setup)

Best for building something non-trivial.

```
Read python/README.md and python/reference.md.
I want to build a small CLI that:
  1. Logs me in
  2. Lists workspaces and lets me pick one
  3. Runs the "Smoke Tests" suite and prints results
```

The README covers retries, timeouts, async clients, and error handling — needed for any non-toy script.

### 3. Type definitions (TypeScript debugging)

When the SDK does something surprising:

```
Read typescript/Client.d.ts and the type definitions under typescript/api/.
Explain why testSuitesRun is returning undefined for me.
Here's my code: <paste>
```

The `.d.ts` files are highly readable; Claude can navigate them without help.

## A minimal end-to-end script

For a candidate dry-run, this is the "hello world":

```python
# hello_zenlabs.py
from zenlabs_sdk import ZenClient

API_BASE = "https://zenarate-web-prod.fly.dev"

# Step 1: log in
boot = ZenClient(token="", base_url=API_BASE)
login = boot.auth.token_auth_login_create(
    username="jane@acme.com",
    password="•••••••••",
)
workspace_id = login.tenants[0].id

# Step 2: authenticated client
client = ZenClient(
    token=f"{login.token} {workspace_id}",
    base_url=API_BASE,
)

# Step 3: do something
me = client.auth.me_retrieve()
agents = client.workflow.workflows.list()

print(f"Hello, {me.email}!")
print(f"You have {len(agents.results)} agents in workspace {workspace_id}.")
```

Run it:

```bash
python hello_zenlabs.py
```

If you see your name and an agent count, the SDK is wired up correctly.
